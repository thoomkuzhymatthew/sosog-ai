## 4. What Broke Or Surprised Me

The maintained tau-bench line has diverged from the original brief's assumption that the Retail verifier is purely programmatic across the whole task set. For the single M1 task (`0`), pass/fail was programmatic: the evaluator reported `db_match=true`, `nl_assertions=[]`, and `review=null`; no LLM review/judge was used for this task. However, the current Retail task file contains 114 base tasks, and 40 of them include non-empty `nl_assertions`. The installed evaluator source (`src/tau2/evaluator/evaluator_nl_assertions.py`) uses an LLM when `nl_assertions` are non-empty. That means the current maintained full Retail run is not purely a free programmatic verifier unless we avoid or change those tasks. This needs a human call before M2.

Other wrinkles:

- The original `sierra-research/tau-bench` repo now says its Retail tasks are outdated; I followed the current maintained README path into `sierra-research/tau2-bench`.
- Core `uv sync` did not install `boto3`/`botocore`; LiteLLM Bedrock required them, so I installed `boto3` into the local tau-bench virtualenv with `uv pip install boto3`.
- LiteLLM's cost lookup did not recognize the normalized Bedrock response model name for cost calculation, so cost is estimated from measured tokens.

## 7. Retail Task Structure

Retail data lives at:

```text

```

Relevant files:

```text

policy.md
split_tasks.json
tasks.json
tasks_voice.json
```

Task counts:

| Split | Count |
| --- | ---: |
| `base` | 114 |
| `train` | 74 |
| `test` | 40 |

The default `base` split is the complete Retail task set. A task contains:

- `id`
- `description`
- `user_scenario.instructions`, including `domain`, `reason_for_call`, `known_info`, `unknown_info`, and `task_instructions`
- optional fields such as `ticket`, `initial_state`, `issues`, `required_documents`, and `user_tools`
- `evaluation_criteria`, including a reference `actions` trajectory, optional `env_assertions`, `communicate_info`, optional `nl_assertions`, and `reward_basis`

Task `0` example:

```text
User: Yusuf Rossi, zip 19122
Goal: exchange two delivered order items from order #W2378156
Expected write: exchange_delivered_order_items
Reward basis: DB + NL_ASSERTION
NL assertions: none for this task
```

For task `0`, the final pass/fail was effectively programmatic because the NL assertion list was empty, so the `NL_ASSERTION` component returned `1.0` without calling a judge.

## 8. Reproduce From Scratch

All commands below assume the repo root:

```text
/Users/joshuajooste/Documents/matthew/StartupSpotter
```

Clone and install tau-bench under `sosog-ai/`:

```bash
cd sosog-ai
git clone https://github.com/sierra-research/tau2-bench tau-bench
cd tau-bench
uv sync
uv pip install boto3
```

Verify install and commit:

```bash
uv run tau2 check-data
git rev-parse HEAD
uv run python - <<'PY'
import tau2
print(tau2.__version__ if hasattr(tau2, "__version__") else "tau2 installed")
PY
```

Smoke-test LiteLLM Bedrock:

```bash
set -a; source ../../.env; set +a
export AWS_DEFAULT_REGION=us-east-1
uv run python - <<'PY'
from litellm import completion
resp = completion(
    model="bedrock/us.anthropic.claude-sonnet-4-6",
    messages=[{"role": "user", "content": "Reply with exactly: TAU2 BEDROCK OK"}],
    max_tokens=16,
    temperature=0,
)
print(resp.choices[0].message.content)
print(resp.usage)
PY
```

Run one Retail task with the stock agent and stock user simulator:

```bash
set -a; source ../../.env; set +a
export AWS_DEFAULT_REGION=us-east-1
uv run tau2 run \
  --domain retail \
  --agent llm_agent \
  --agent-llm bedrock/us.anthropic.claude-sonnet-4-6 \
  --agent-llm-args '{"temperature": 0.0}' \
  --user user_simulator \
  --user-llm bedrock/us.anthropic.claude-sonnet-4-6 \
  --user-llm-args '{"temperature": 0.0}' \
  --num-trials 1 \
  --task-ids 0 \
  --max-concurrency 1 \
  --max-retries 0 \
  --timeout 900 \
  --save-to sosog_m1_retail_task0_bedrock_sonnet46 \
  --verbose-logs \
  --llm-log-mode all \
  --log-level INFO
```

Re-run the built-in evaluator on the saved trajectory:

```bash
set -a; source ../../.env; set +a
export AWS_DEFAULT_REGION=us-east-1
uv run tau2 evaluate-trajs \
  data/simulations/sosog_m1_retail_task0_bedrock_sonnet46/results.json
```

Inspect metrics and task structure:

```bash
jq '.simulations[0].reward_info' \
  data/simulations/sosog_m1_retail_task0_bedrock_sonnet46/results.json

jq '{base:(.base|length), train:(.train|length), test:(.test|length)}' \
  data/tau2/domains/retail/split_tasks.json

jq '[.[] | select((.evaluation_criteria.nl_assertions // []) | length > 0)] | length' \
  data/tau2/domains/retail/tasks.json

jq -s '{
  calls:length,
  prompt_tokens:(map(.response.usage.prompt_tokens // 0) | add),
  completion_tokens:(map(.response.usage.completion_tokens // 0) | add),
  total_tokens:(map((.response.usage.prompt_tokens // 0) + (.response.usage.completion_tokens // 0)) | add)
}' \
  data/simulations/sosog_m1_retail_task0_bedrock_sonnet46/artifacts/task_0/*/llm_debug/*.json
```
