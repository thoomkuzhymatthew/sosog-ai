# M11 Task Decomposition

Date: 2026-08-20

Status: stopped for review after the required 1-2 task proof. No scaling to the remaining candidates.

## Headline

M11 is **not cleanly proven yet**.

The deterministic-prefix part worked: all six M11 candidates have all-run, read-only safe prefixes whose outputs match the saved M3 traces and repeat under fresh deterministic execution. But the first live proof was mixed:

- `78` preserved pass rate: M3 `10/10` -> M11 `10/10`.
- `97` did **not** preserve pass rate: M3 `10/10` -> M11 `9/10`.

Because the first 1-2 proof did not work cleanly, I stopped and did **not** run `30`, `87`, `100`, or `112`.

This deflates the M11 portion of the M3 recovery estimate for now: of the $1.225408 M2 baseline cost routed to M11, only task `78`'s $0.218135 is proven recoverable by this experiment. The remaining $1.007273 is still plausible but unproven, and should not be counted until the handoff behavior is made safer.

## Method

I used `traces/m3/retail_db_checkable_n10_final_valid.jsonl` and the harness in `scripts/run_m11_decomposition.py`.

For each candidate, the harness aligned all 10 saved traces by exact tool name and arguments, found the longest common prefix, then truncated that prefix at the first write or unknown tool. The prefix executor calls only retail read tools and reports `prefix_model_calls = 0`.

For the first proof tasks, the tail runs used `bedrock/us.anthropic.claude-sonnet-4-6` at temperature `0.0`. The handoff retained the saved pre-divergence conversation with prior usage/cost stripped, replayed saved post-handoff user messages at zero model cost, and measured tail assistant usage from message usage counters. There was no quota block.

## Prefix Determinism

No prefix was hand-picked from passing runs. The safe prefixes above are strict all-10 leading prefixes across passing and failing/divergent runs.

For all six candidates:

- Prefix calls were read-only after safety truncation.
- Fresh deterministic execution reproduced the saved prefix outputs.
- Saved M3 trace prefix output hashes matched the crystallized prefix output hashes for all 10 trials.
- The handoff gate caught deliberately corrupted prefix state.
- Prefix execution made zero model calls.

Important caveat: task `100` has a 10-step raw LCP, but step 10 is a write. The crystallizable prefix is only the first 9 read-only steps; the common write remains in the volatile tail.

## Why The Proof Stopped

Task `97` trial 6 failed without any write. The handoff state was well-formed and deterministic, and the last saved user message before the tail already said to proceed with both changes. In the decomposed tail, the agent asked for an even clearer confirmation instead of performing the writes; the replayed saved user tail then stopped. The DB verifier therefore failed.

That is a handoff/tail-behavior regression, not a prefix-determinism failure. It still violates the M11 requirement: decomposition must not reduce correctness.

## Handoff Safety

The boundary gate is useful but incomplete:

- It catches malformed prefix packets, write tools in the prefix, tool errors, and missing required fields.
- It does not guarantee the tail agent will interpret an already-confirming user message as sufficient authorization. Task `97` shows that a valid handoff can still change behavior.

So the next M11 iteration should focus on tail handoff semantics, not more prefix extraction. Do not scale to the other four tasks until `97` can preserve pass rate without adding verifier-specific hints.
