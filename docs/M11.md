# M11 Task Decomposition

Date: 2026-08-20

Status: complete through N=20 scale coverage. Stop for review.

## Headline

M11 is validated, but with a real boundary: decomposition is **task-dependent**, not universally safe or universally cost-saving.

The deterministic-prefix mechanism itself worked. Across all successful decomposed rows, the prefix was read-only, deterministic, and made zero model calls. The boundary is in the handoff/tail:

- `78`, `97`, and `30` preserved correctness and saved cached cost.
- `87` preserved correctness but cost more under the current handoff.
- `112` is noisy in both arms; the final one-run decomposed deficit is within noise, and the handoff is cost-negative.
- `100` did **not** preserve correctness: baseline stayed perfect while decomposed runs repeatedly chose the wrong volatile-tail writes.

Scale was resumed after the US Bedrock daily-token quota using `bedrock/global.anthropic.claude-sonnet-4-6`, per review direction. The final scale corpus has 160 successful rows: 137 successful rows from the original US-profile run plus 23 successful rows from the global-profile resume. The old quota-error row remains in the JSONL audit trail but is excluded from metrics.

Cost-weighted against the original $1.225408 M2 baseline routed to decomposition:

- **Clean cost-win with correctness preserved:** `78`, `97`, `30` = **$0.663993** of routed M2 baseline.
- **Correctness preserved / within-noise, but not a cost win:** `87`, `112` = **$0.390109**.
- **Not safely recoverable by decomposition:** `100` = **$0.171306**.

So M11 does not recover the full $1.23 bucket. The current clean economic recovery is about **$0.664**, with another **$0.390** technically decomposable but not economically useful unless the handoff is improved.

## Method

I used the saved M3 corpus in `traces/m3/retail_db_checkable_n10_final_valid.jsonl` to align each candidate by exact tool name and arguments, then truncated each prefix before the first write. The crystallized prefix executor calls only retail read tools and records `prefix_model_calls = 0`.

Scale measurement used `scripts/run_m11_scale.py`: stock full-agent baseline versus crystallized prefix -> stock Sonnet tail. Both arms used Claude Sonnet 4.6, temperature `0.0`, the live Sonnet user simulator, prompt caching enabled, and matched seeds interleaved by task and arm.

Model/profile note: rows before the quota stop used `bedrock/us.anthropic.claude-sonnet-4-6`; the final 23 successful rows used `bedrock/global.anthropic.claude-sonnet-4-6`. Both profiles are Sonnet 4.6, but the final scale corpus is mixed-profile.

The runner is resume-safe. Existing successful `(task, arm, trial)` rows are skipped on resume, and per-row model metadata is recorded for resumed rows.

## Task 100 Boundary

Task `100` is the important negative result. Its prefix was clean in every completed decomposed run: expected read count `9/9`, zero prefix model calls, and no malformed handoff. Correctness still dropped from `20/20` baseline to `14/20` decomposed.

The failures were not random DB corruption. They were volatile-tail decision errors after the handoff, usually choosing the wrong replacement SKU for the pending order and once adding an extra/wrong return payment write. This matches the earlier caveat for `100`: the raw common prefix has 10 steps, but step 10 is a write, so the safe crystallized prefix must stop one step earlier. The tail appears to rely on reasoning context around that excluded write decision. Crystallizing only the reads saves tokens, but it changes the tail enough to hurt correctness.

Conclusion: task `100` should **not** be counted as recoverable via M11 under the current handoff, even though it shows positive token/cost savings.

## Task 112 Noise Check

Task `112` does not show a reliable decomposition-caused harm signal. Baseline finished `18/20`; decomposed finished `17/20`. Failures appeared in both arms, including the same write skeleton on matched trial 9. The one-run difference is within the noise the prompt warned not to over-interpret.

However, `112` is not an economic win in this implementation: decomposed total cached cost was $0.680304 higher than baseline over the 20 matched pairs.

## Prefix Determinism And Safety

No prefix was hand-picked from passing runs. The safe prefixes are strict all-10 leading prefixes from the saved M3 traces, truncated before any write.

For all six candidates:

- Prefix calls were read-only after safety truncation.
- Fresh deterministic execution reproduced the saved prefix outputs.
- Saved M3 trace prefix output hashes matched crystallized prefix output hashes.
- The handoff gate caught deliberately corrupted prefix state.
- Completed decomposed rows made zero model calls in the prefix.
- The N=20 scale run recorded zero completed-run prefix safety violations.

The only non-task row in the scale JSONL is the earlier task-30 decomposed trial-17 quota block from the US run. It occurred before a task result was produced and is excluded from final metrics.

Measured cached-cost savings are sample-size dependent and should not be compared directly to single-run M2 baseline dollars. They still show the same direction:

- Positive and correctness-preserving: `78` + `97` + `30` saved **$1.866233** across their measured samples.
- Correctness-preserving / within-noise but cost-negative: `87` + `112` cost **$1.135562** more across their measured samples.
- Unsafe despite apparent savings: `100` saved **$0.733395** over 20 matched pairs, but failed correctness preservation and must be excluded.

## Decision

M11 is worth keeping as a targeted technique, not as a blanket rescue for every stable-prefix flaky task.

The actionable rule is now sharper:

1. Crystallize only all-run, read-only deterministic prefixes.
2. Require a matched A/B correctness check, not just prefix validation.
3. Count a task as recovered only if correctness is preserved and measured cost actually drops.
4. Reject tasks like `100`, where the volatile tail depends on reasoning around the excluded write decision.

M11 validates a real decomposition opportunity, but the recoverable value is materially smaller than the original $1.23 routed bucket: the clean recoverable slice is about **$0.664** of M2 baseline cost.
