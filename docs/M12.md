# M12 Exemplar Lifting

Date: 2026-08-21

Status: proof checkpoint. Model-pure Sonnet 4.6. Stopped for review before scaling beyond the first validated task.

## Headline

M12 works on the first proof task.

Task `49` improved from **6/20 baseline** to **20/20 lifted** using two successful M3 trace exemplars in the agent context. The lift crossed the promotable threshold, had **14 newly passing paired trials**, and had **0 regressions**.

This is a real behavior improvement, not a verifier shortcut. Baseline failures consistently chose item `8555936349`, the cheapest IPX4 catalog variant, but that item was not in the user's order. Lifted runs read the user's order, found item `1646531091` as the cheapest eligible Wireless Earbuds item from the rest of the same order, confirmed with the user, and wrote the correct exchange.

Confirmed recoverable so far: **1/8 lift candidates**, worth **$0.167902** of the **$1.469438** routed to lifting. The remaining **$1.301536** is not counted as recovered until scaled and anti-gaming checked.

Exemplar cost note: the exemplar context was **14,199 chars** and added **376,732 agent prompt tokens** across the 20 lifted runs. Because the lifted agent needed fewer calls and shorter completions, measured agent cached cost still fell by **$0.616152** for this task. That cost reduction is a side effect of cleaner execution; lifting should still be treated as an added-context cost unless it reliably raises pass rate.

## Correctness Of Lift

Task `49` passed the anti-gaming check.

Baseline failure pattern:

```text
exchange_delivered_order_items(
  item_ids=["2757705742"],
  new_item_ids=["8555936349"],
  order_id="#W3470184",
  payment_method_id="gift_card_7245904"
)
```

This is wrong because `8555936349` is a cheaper catalog variant, not one of the Wireless Earbuds already in order `#W3470184`.

Lifted pass pattern:

```text
exchange_delivered_order_items(
  item_ids=["2757705742"],
  new_item_ids=["1646531091"],
  order_id="#W3470184",
  payment_method_id="gift_card_7245904"
)
```

I inspected newly passing lifted trials `1` and `15`. In both, the agent authenticated the user, read all candidate orders, found delivered order `#W3470184`, listed the in-order Wireless Earbuds options, identified `1646531091` as the cheapest eligible replacement from that same order, got user confirmation, and only then wrote the exchange. This is the correct path, not a verifier artifact.

## Decision

M12 is validated on task `49`: exemplar lifting can rescue an agent-wandered flaky task into promotable territory without gaming the verifier.

I did not scale to the other seven lift candidates yet. Next step after review is to run the same N=20 baseline-vs-lifted protocol on `41`, `74`, `79`, `94`, `96`, `98`, and `99`, with the same anti-gaming inspection before counting any cost as recovered.
