# M2 - DB-Checkable Retail Baseline

Date: 2026-08-17

## 1. What Was Built

M2 is complete as a standalone cached on-demand baseline over the DB-checkable Retail task set. I filtered the maintained tau2 Retail tasks to exclude LLM-judged `nl_assertions`, enabled Bedrock prompt caching on the stable policy/system prefix without changing the prompt text, ran the full filtered set once with the stock `llm_agent`, re-ran the built-in verifier over the saved trajectories, and exported one JSONL trace per simulation.

No custom SOSOG engine code was added.

Local changes made for M2:

- `sosog-ai/config/retail_db_checkable_task_ids.json`: saved the DB-checkable working set.
- `sosog-ai/tau-bench/src/tau2/utils/llm_utils.py`: added an env-gated Bedrock prompt-cache checkpoint and Sonnet 4.6 cache-aware cost calculation.
- `sosog-ai/scripts/export_m2_baseline.py`: exports summary metrics, per-task CSV, and JSONL traces from the saved tau2 run.
- `sosog-ai/metrics/m2_baseline_summary.json`: machine-readable M2 summary.
- `sosog-ai/metrics/m2_per_task_costs.csv`: per-task cached and uncached-counterfactual costs.

## 3. Prompt Caching

Prompt caching is enabled with:

```bash
export TAU2_BEDROCK_PROMPT_CACHE=1
```

Implementation detail: the patch adds `cache_control: {"type": "ephemeral"}` to the last stable system message for Bedrock model calls. It does not alter prompt text, trim the Retail policy, modify tool schemas, or change generation parameters. The baseline prompt behavior is therefore unchanged; only Bedrock's pricing/latency path changes.

AWS Bedrock's prompt caching documentation says Claude Sonnet 4.6 supports cache checkpoints in `system`, `messages`, and `tools`, with a 1,024-token minimum and 5-minute TTL. The same page notes prompt caching is for on-demand inference and is not supported by the batch inference API. Sources:

- https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html
- https://aws.amazon.com/bedrock/pricing/

Measured cache usage in this M2 run:

| Agent calls | 842 |

| Cache write calls | 2 |

| Cache read input tokens | 4,230,240 |

Only the agent side showed cache write/read usage. The user simulator had 0 cache creation tokens and 0 cache read tokens.

Three notes:

- tau2 prints many LiteLLM provider-list banners during Bedrock calls. They were noisy but non-fatal.
- tau2's top-line cost metric is agent-only; benchmark spend needs the user-simulator split included.
- Action diagnostics can disagree with DB pass/fail. Several tasks passed DB match while action diagnostics were partial, so M2 treats DB/pass reward as the headline and action checks as diagnostics.

## 10. Reproduce

All commands below assume the repo root:

```text
/Users/joshuajooste/Documents/matthew/StartupSpotter
```

Run the cached full DB-checkable baseline:

```bash
cd sosog-ai/tau-bench
bash -lc '
TASK_IDS=($(jq -r ".kept_task_ids[]" ../config/retail_db_checkable_task_ids.json))
set -a
source ../../.env
set +a
export AWS_DEFAULT_REGION=us-east-1
export TAU2_BEDROCK_PROMPT_CACHE=1
uv run tau2 run \
  --domain retail \
  --agent llm_agent \
  --agent-llm bedrock/us.anthropic.claude-sonnet-4-6 \
  --agent-llm-args "{\"temperature\": 0.0}" \
  --user user_simulator \
  --user-llm bedrock/us.anthropic.claude-sonnet-4-6 \
  --user-llm-args "{\"temperature\": 0.0}" \
  --num-trials 1 \
  --task-ids "${TASK_IDS[@]}" \
  --max-concurrency 2 \
  --max-retries 1 \
  --retry-delay 5 \
  --timeout 900 \
  --save-to sosog_m2_retail_db_checkable_cached_baseline \
  --verbose-logs \
  --llm-log-mode all \
  --log-level INFO
'
```

Re-evaluate saved trajectories:

```bash
cd sosog-ai/tau-bench
uv run tau2 evaluate-trajs data/simulations/sosog_m2_retail_db_checkable_cached_baseline/results.json
```

Export M2 metrics and traces:

```bash
cd /Users/joshuajooste/Documents/matthew/StartupSpotter
python3 sosog-ai/scripts/export_m2_baseline.py
```
